# 专辑编辑中的发行参考验收

后台扫描仍自动保存高置信度的缺失信息。编辑弹窗同时提供在线查到的发行参考，供用户判断未能自动确定的信息并人工修正。

## 预期行为与失败方式

| 场景 | 预期 |
| --- | --- |
| 开启在线查询 | 打开弹窗即读取候选，复用现有缓存、限流和版本校验；不要求先点击查询 |
| 存在候选 | 展示发行日期、地区、格式、曲目数、流派、艺人及 MusicBrainz 来源 |
| 发行版本不一致 | 明示曲目数、分碟、艺人或年份差异；不把这些候选标成自动匹配成功 |
| 采用候选 | 仅修改草稿中候选提供的年份和流派；缺失字段不清空原输入；取消不写库，保存才成为人工修正 |
| 查询晚到 | 仅展示参考，不自动写入草稿，不覆盖正在编辑的字段；关闭弹窗时取消读取 |
| 网络失败、无结果或在线能力关闭 | 显示对应状态；手动输入与保存保持可用；网络错误可以重试 |
| 查询期间数据更新 | 保留草稿并提示版本冲突，明确重新载入后再继续；不能覆盖其他设备的更新 |
| 候选较多、详情不完整或结果截断 | 默认紧凑展示，可展开更多；标明不完整，不伪装成完整匹配结果 |
| 桌面和移动端 | 保持现有弹窗样式、紧凑文字与间距；内容不横向溢出，输入和保存操作可到达 |

## 验证

先增加针对性 E2E，用隔离曲库、真实查询/保存 API 和可控的外部 MusicBrainz 边界验证。覆盖候选选用/取消/保存、迟到响应、失败重试、空结果、关闭在线能力、查询冲突和多候选；保留桌面及移动端截图、trace、请求记录、音频哈希和 SQLite 校验。

本次不降低后台补全的判断标准，不修改音乐文件，不增加数据库字段或 API 契约。交付前运行类型检查、构建、差异检查及相关 E2E。
