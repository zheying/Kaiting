# 测试整改验收需求

先列行为和失败模式，再实现测试、迁移和合并。所有音乐都是在临时目录生成的 fixture，不读取真实曲库、`.env` 或运行时用户数据。每例独立服务、SQLite 和浏览器上下文，服务使用生产构建。

| 流程 | 预期行为与关键失败模式 |
| --- | --- |
| 账号 | 页面登录和退出、首次临时密码必须改密、普通账号不能进入管理操作、会话撤销后回登录并能返回原页面；当前数据库会话应拒绝伪造/过期/撤销凭据，并遵守 Cookie 传输配置 |
| 扫描 | 界面选择目录启动真实扫描，结束后列表刷新；未改动重扫跳过解析；坏音频显示部分失败，停止和目录离线不能清空已有索引、收藏或歌单 |
| 播放 | AAC 直传、ALAC/FLAC 转码能实际播放；键盘/拖动 seek、暂停/继续、自然结束重播和刷新恢复不从曲尾请求空流；队列切歌/循环有效，不伪造媒体事件 |
| 歌单 | 创建/添加/键盘及指针排序/保存/刷新/重命名/移除/删除；创建响应丢失或添加失败后重试不重复创建，重复操作幂等；409 保留草稿，账号间隔离 |
| 目录浏览 | 含中文/%/斜杠的搜索、专辑和艺人导航、收藏持久化；大于一页的队列完整；部分 API 失败可重试，晚到的旧请求不能覆盖当前状态 |
| 专辑信息 | 开启在线能力后，初次扫描和新增专辑后的完整扫描默认在后台补全，不打开弹窗、不点击查询或保存也会持久化可靠结果；编辑入口对已有信息的专辑同样可用，仅用于人工修正；歧义/网络失败不猜填、不阻塞本地扫描；后台晚到结果不能覆盖人工设置，409 保留输入直到明确重新载入 |
| 移动端 | 手机 UA 胶囊播放器→全屏→歌词/队列，触摸操作和进度有效；桌面窄屏/恢复宽屏与 iPad UA 保持既有布局规则；登录背景 reduce-motion、尺寸变化和重新进入不残留循环 |
| 维护 | 构建后的 CLI 备份→空目录恢复→重新启动服务→页面读回收藏/歌单/缓存；源音乐哈希不变，数据库完整，缓存路径重定位 |
| 测试入口 | E2E 无文件/功能名不隐式跑全量；支持预览、按 spec/功能/用例选择；CI 明确包含全部层级、检查浏览器和 FFmpeg 并产出报告 |

失败注入仅在可观察边界：浏览器网络请求、隔离上游服务、临时目录挂载/文件、独立真实客户端引发的版本冲突。测试观察媒体事件驱动的页面进度及 HTTP 请求，不改音频 currentTime、不手动 dispatch ended、不访问 React 内部状态。

迁移/合并原则：当前账号的安全契约补齐后仍保留兼容分支专属测试；生产与原型共享验证表；重复成功流程的独有断言先移入客户端契约测试。旧代码仍存在且仍可能被独立使用的测试保留在 legacy 范围，不凭“当前未引用”直接删除源码。

产物：Playwright JSON/JUnit/HTML 报告、逐例截图、trace、服务日志、网络记录、fixture 哈希及 SQLite 校验结果。复验按单一功能执行，完成整改后不默认运行全部既有测试。

## 后台补全与人工修正的职责

本次实现前确定的验收边界：

- 在线能力总开关开启后，专辑后台补全默认开启，仍允许显式关闭；总开关关闭时不请求上游。
- 不打开专辑信息弹窗也能完成首次补全；新增专辑后的增量扫描同样触发，已打开的专辑列表自动更新。
- 只保存可靠匹配的缺失年份和流派；完整性、艺人、曲目数、发行版本及目录变化等现有保护不放宽。
- 弹窗删除按需自动查询和候选选择，提供已有值的编辑、来源、保存及恢复扫描信息。信息完整的专辑也能进入编辑。
- 人工保存、清空或恢复优先于后台任务，重新扫描和服务重启不能重新覆盖；并发编辑冲突保留当前草稿。
- 上游慢或失败不拖住本地扫描，歧义结果留空；自动重试仍有上限，不要求用户点击弹窗按钮恢复。
- 使用独立测试曲库生成新专辑，结束后比对全部源文件哈希及 SQLite 完整性；保留桌面和手机弹窗截图。

实现参考：[Playwright fixtures](https://playwright.dev/docs/test-fixtures)、[测试配置](https://playwright.dev/docs/test-configuration)、[网络边界](https://playwright.dev/docs/network)。
