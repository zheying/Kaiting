## 结论

主要页面的视觉框架基本还原，扫描成功结果页也已接入真实数据；但尚未达到“原型体验完整落地”的验收标准。本轮确认 **2 项 P1、2 项 P2，以及 2 项 P3 排版问题**。缺口集中在局域网 HTTP 兼容、接口局部失败、弹窗内错误反馈和真实艺人数据。

优先级含义：P1 为应优先修复的核心流程阻断；P2 为影响常用交互或异常恢复的问题；P3 为排版细节。优先级不表示发生概率或安全漏洞等级。

| 编号 | 优先级 | 已确认问题 | 证据环境 |
| --- | --- | --- | --- |
| F1 | P1 | 局域网 HTTP 下创建歌单直接报错，界面没有反馈 | 同构建、同访问协议的隔离 QA |
| F2 | P1 | 专辑或歌单详情接口失败，整个曲库浏览不可用 | 同构建隔离 QA 的 503 故障注入 |

| F4 | P2 | 艺人目录与搜索遗漏歌曲艺人，搜索和详情结果矛盾 | 正式 NAS 真实曲库 |
| V1 | P3 | 专辑主标题与副标题重复显示同一字段 | 正式 NAS、隔离 QA 手机视口 |

## 审计环境和证据边界

- 正式目标：`http://192.0.2.10:3002`，桌面 CSS 视口 `1108 × 879`。本轮读取到 1,045 首歌曲、12 张专辑。
- 原型：`http://127.0.0.1:4173`，桌面相同 CSS 视口。原型有额外的“状态总览／交互预览”栏，数量和演示账号与正式不同，这些不计为视觉缺陷。
- 隔离 QA：`http://127.0.0.1:4180`，使用独立数据库及测试音乐目录。局域网 HTTP 场景通过本机 LAN 地址访问同一 QA 服务；故障代理仅绑定 `127.0.0.1:4182`。
- 正式 NAS 与隔离 QA 加载同一前端 bundle：`assets/index-DF2qgGqd.js`。HTTP 创建歌单问题在 QA 实测，结合相同构建和部署协议判断正式环境也受影响；没有在正式 NAS 提交测试歌单。
- 手机测试采用 `393 × 852` CSS 视口模拟，不是实体手机验收。QA 保持已有深色偏好，NAS 为浅色；不将两种主题截图直接作颜色差异比较。
- 本轮所有截图均为实际渲染页面。原型与正式截图的输出密度可能不同，因此结论为结构、布局、状态与交互审查，不宣称全站逐像素一致。
- 正式环境操作限定为浏览、搜索和打开弹窗；未触发扫描、修改目录、创建账号、写入歌单或操作原始音乐文件。故障注入仅针对隔离 QA，失败的扫描启动请求未转发到扫描器。

## F1 · P1：局域网 HTTP 下不能创建歌单

**复现：** 在 LAN HTTP 地址打开隔离 QA，登录后新建歌单，输入有效名称“审计临时歌单”，点击“创建歌单”。

**实际：** 弹窗停留，没有成功结果或可见错误提示。浏览器控制台抛出 `TypeError: crypto.randomUUID is not a function`，没有创建出歌单。

**原因：** [Room.tsx:332](../../../src/client/room/Room.tsx#L332) 直接调用 `crypto.randomUUID()`；调用发生在 `saveChange` 的异常处理外。当前 LAN HTTP 环境没有这个方法，localhost 验收未暴露该问题。

**建议：** 幂等请求 ID 的生成需要兼容受支持的局域网 HTTP 部署，并纳入表单错误处理。验收应覆盖“普通 HTTP LAN 地址创建成功、刷新仍存在、失败时弹窗内可见提示”，不能只检查 localhost。

证据：失败后的弹窗（原始附件已转存私有验收资料）、控制台错误（原始附件已转存私有验收资料）。

## F2 · P1：局部请求失败导致整个曲库不可用

**复现：** 在隔离 QA 中分别令专辑列表接口 `GET /api/albums`、歌单详情这一类接口 `GET /api/playlists/:id` 返回 503，其他请求正常；刷新页面。第二次故障注入匹配所有歌单详情请求，并非只拦截某一个歌单。

**实际：** 两种情况均进入“暂时无法打开音乐库”整页错误。首屏侧栏显示 0 首／0 张专辑，播放器失去当前内容，歌曲和搜索也无法继续浏览。恢复接口后“重新尝试”能恢复曲库，未发生数据删除。

**与原型的差距：** 原型已设计[列表失败](http://127.0.0.1:4173/#/preview/list-error)、[详情失败](http://127.0.0.1:4173/#/preview/detail-error)及[搜索部分失败](http://127.0.0.1:4173/#/preview/search-partial)。正式路径尚未按数据区域承接这些降级状态。

**原因：** [data.ts:35](../../../src/client/room/data.ts#L35) 至 [data.ts:56](../../../src/client/room/data.ts#L56) 要等待歌曲、统计、专辑与所有歌单详情一起成功才更新数据；任意失败都改为全局 error，因此从代码逻辑看，单个歌单详情失败也足以触发此问题。[Room.tsx:764](../../../src/client/room/Room.tsx#L764) 随后拦截整个曲库页面。搜索局部错误条件仍绑定原型的 preview 路由（[Room.tsx:663](../../../src/client/room/Room.tsx#L663)）。

**建议：** 按歌曲、专辑、歌单及详情分别维护请求状态，保留已经可读的数据，提供区域内重试；真正无法连接整个服务时才展示全局错误。回归测试至少包含“一个私人歌单详情失败，仍能浏览歌曲和专辑”。

证据：专辑请求失败（原始附件已转存私有验收资料）、歌单详情请求失败（原始附件已转存私有验收资料）、经过筛选的请求记录（原始附件已转存私有验收资料）。这些截图是故障注入结果，不表示 NAS 当前服务故障。

## F3 · P2：设置弹窗挡住扫描启动失败提示

**复现：** 手机视口打开设置，点击“重新扫描”；隔离代理令 `POST /api/scan` 返回 503，拦截请求，不启动实际扫描。

**实际：** 页面仍停留在设置弹窗，看不到失败原因，也没有进入原型的“无法启动扫描”页。DOM 已存在 `toast visible`，但提示位于原生模态 dialog 的顶层之外，被弹窗遮挡。

**原因：** [Room.tsx:260](../../../src/client/room/Room.tsx#L260) 失败分支只调用全局 `announce`，不更新扫描失败状态；[Room.tsx:903](../../../src/client/room/Room.tsx#L903) 的 toast 位于 modal 外。

**建议：** 在设置或目录选择弹窗内呈现失败原因与重试入口，或关闭弹窗并进入完整[扫描失败状态页](http://127.0.0.1:4173/#/preview/scan-failed)。其他弹窗中的 API 错误也需检查，不能仅靠提高普通元素的 z-index 解决原生 dialog 的顶层关系。

证据：失败后的手机设置弹窗（原始附件已转存私有验收资料）、toast 和 dialog 的 DOM 状态（原始附件已转存私有验收资料）。

## F4 · P2：歌曲艺人在目录和搜索中缺席

**复现：** 在正式 NAS [搜索 ACE+](http://192.0.2.10:3002/#/search?q=ACE%2B)，结果为“0 位艺人 · 0 张专辑 · 29 首歌曲”；点击播放器的 ACE+，可进入[ACE+ 艺人详情](http://192.0.2.10:3002/#/artist/ACE%2B)，其中有“2 张专辑 · 29 首作品”。

**实际影响：** 用户明知歌曲属于某位艺人，却无法从艺人目录或艺人搜索入口找到该艺人。歌曲没有丢失，是入口索引不一致。

**原因：** [Room.tsx:572](../../../src/client/room/Room.tsx#L572) 与 [Room.tsx:634](../../../src/client/room/Room.tsx#L634) 只从专辑的 artist 生成艺人集合；详情页却同时匹配歌曲 artist。

**建议：** 统一艺人索引来源与目录、搜索、详情的匹配规则，纳入歌曲艺人；明确专辑艺人与参与创作者的关系，避免用“多位艺人”或整段联合署名替代所有可浏览创作者。

证据：搜索显示 0 位艺人（原始附件已转存私有验收资料）、同一艺人的详情有 29 首作品（原始附件已转存私有验收资料）。

## 真实内容暴露的排版问题

**V1 · P3：专辑标题重复。** 正式详情的主标题和下方副标题均显示同一专辑名，长标题时额外挤占首屏。`mapAlbum` 将 name 与 title 都映射为 API title（[data.ts:14](../../../src/client/room/data.ts#L14)），详情又无条件显示两次（[Room.tsx:560](../../../src/client/room/Room.tsx#L560)）。建议只有译名／别名与原标题确实不同才显示第二行，不需要补造翻译。证据：NAS 专辑详情（原始附件已转存私有验收资料）、手机专辑详情（原始附件已转存私有验收资料）。

**V2 · P3：艺人卡片封面错齐。** 真实署名有一行、两行、三行，首排三个封面的上边缘随文字高度不同而错开。建议卡片内容顶部对齐，并给标题制定明确的换行和截断规则，保留完整名称的可访问方式。证据：NAS 艺人网格（原始附件已转存私有验收资料）。
