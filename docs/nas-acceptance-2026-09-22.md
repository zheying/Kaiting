# Mac 连接真实 NAS 曲库验收

日期：2026-09-22。目标：在当前 Mac 上验证第一轮修复能否支撑真实曲库使用，并修复验收中发现的问题。

## 环境与隔离

- 使用 Mac 上已挂载的 NAS 音乐目录、Node v26.0.0、FFmpeg 8.0.1 和 Chrome 桌面浏览器。
- 运行生产构建，通过 `http://127.0.0.1:56359` 访问。未占用已有的 3000 端口服务。
- 原数据库通过 SQLite backup API 复制，封面和元数据缓存复制到独立临时 `DATA_DIR`；歌曲直接从 NAS 只读读取。
- 只在副本中迁移缓存绝对路径，包括 `tracks` 的封面/歌词路径和 `metadata_cache.payload`。歌曲路径与 ID 保持原值。
- 临时随机密码和 Cookie 密钥，`COOKIE_SECURE=false`，在线元数据关闭；没有创建正式 `.env` 或安装常驻服务。
- 收藏、验收歌单及扫描记录只写入副本。验收结束后停止临时服务并删除副本及临时凭据。

## 结果

| 检查 | 证据与结论 |
| --- | --- |
| 原曲库就绪 | 有效数据库为 `data/music-library.sqlite`；1,054 首、11 张专辑、6 位艺人。`data/library.sqlite` 是空文件，不作为当前数据库使用 |
| 数据完整性 | 原库 `quick_check=ok`，副本 `integrity_check=ok`，外键检查无错误，FTS 与歌曲数量一致 |
| 文件可读 | 全部 1,054 条索引经过 `safeRealPath`、文件状态及读取权限检查，均可访问，大小和修改时间与索引一致 |
| 格式范围 | 真实库全部是 ALAC M4A；本轮真实歌曲验收覆盖转码，未覆盖真实 AAC/MP3/FLAC 直传 |
| API 与资源 | 未登录接口返回 401；登录成功。分页 API 分三页取得全部 1,054 首且无重复。抽样封面和歌词返回内容与缓存一致 |
| 实际转码 | 两首超过 4 分钟的歌曲分别从 0 秒、30 秒请求，返回 `audio/mpeg`；各读取约 128 KiB，用 FFmpeg 解码前 3 秒成功 |
| 首字节记录 | 两次抽样分别为 44 ms、33 ms；仅为本机当次验收记录，不能代表冷缓存、远程或 NAS 上的性能 |
| 浏览器首播与切歌 | 真实短曲进度从 0 到 5 秒，约 9 秒自然结束后自动播放下一首；下一首进度继续增长 |
| 暂停与拖动 | 暂停后时间保持 13 秒；另一首向后定位到 1 秒、向前拖到 1:59，随后继续推进到 2:46 |
| 页面刷新续播 | 暂停于 2:46 后刷新，登录、当前歌曲和位置恢复；点击播放后进度推进到 3:11，最终于 4:00 自然结束并停止。这里只验证同一标签页刷新，未验证关闭浏览器后的恢复 |
| 服务中断恢复 | 停止服务后选择未加载的歌曲，显示失败与重试；恢复服务后点击重试，错误消失且进度推进 |
| 重启持久化 | 使用相同 `DATA_DIR` 和密钥重启，复用原 Cookie 仍可访问；收藏状态、验收歌单三首歌曲及顺序一致 |
| 转码进程清理 | 限速读取时确认 FFmpeg 活跃，客户端断开后退出；活跃转码期间向本次服务发送 SIGTERM，记录的两个子进程均退出 |
| 全库重扫 | 修复后扫描 1,054/1,054，约 6.9 秒，0 错误；歌曲 ID、路径、收藏和歌单关系不变；1,054 个封面和 3 份歌词保留，三份歌词均再次通过 API 读取 |
| 原始数据保护 | 原数据库及 WAL 的 SHA-256 与验收前一致；全部 1,054 首音乐的大小、修改时间未变 |

浏览器结果依据实际播放进度和状态变化，测试中播放器静音，未进行主观音质听测。服务中断测试不等同于真实 NAS 掉线或手机网络切换。

## 本轮发现并修复

关闭在线元数据后重扫，扫描器只重新发现本地资源，原有在线歌词引用会被 `null` 覆盖。真实数据副本复现：扫描前 3 份歌词，扫描后 0 份；文件仍在缓存中，但播放器无法再访问。

修复在扫描合并阶段保留仍存在、通过 `safeRealPath` 验证且为普通文件的缓存封面和歌词。新发现的本地歌词、内嵌封面及目录封面优先。缺失、目录、越界和指向目录外的符号链接不会作为缓存保留。

新增 7 项扫描回归测试；修复后同一真实曲库重扫仍保留 3 份歌词。最终验证：

- `npm test`：10 个文件、149 项测试通过。
- `npm run typecheck`：通过。
- `npm run build`：通过。
- `git diff --check`：通过。

## 后续边界

1. **曲库完整浏览与播放**：API 可取全库，但首页仍只显示 60 首，“播放全部”也只取这 60 首；收藏、专辑/艺人列表及搜索范围的分页问题仍待第二轮处理。
2. **真实手机验收**：iPhone/Android 首播、锁屏与后台播放、耳机控制、网络切换和持续听歌尚未验证。桌面 Chrome 的结果不能替代这些检查。
3. **NAS/Docker 部署**：没有进行镜像构建、容器运行、NAS 主机部署或 HTTPS 反向代理验收。现有数据库存储主机绝对路径，不能直接挂到 `/music`、`/data` 后就认定可用；迁移时应备份并转换歌曲、缓存和关联数据，保留收藏/歌单所使用的歌曲 ID。
4. **长期稳定性**：本轮是核心流程验收，不是数小时连续播放或断网耐久测试；真实 NAS 卸载、服务异常崩溃及备份恢复仍需专项验证。
