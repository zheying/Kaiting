## 2. 优先处理的基础问题

### P0：生产鉴权与部署配置

**已确认：** `src/server/config.ts:46` 在生产环境仍回退到公开固定的 Cookie 密钥；`auth.ts:8`、`:18` 仅凭该密钥验证会话。临时实例中，无会话请求返回 401，使用默认密钥生成的会话返回 200，无需管理员密码。

`docker-compose.yml:8` 硬编码密码与在线元数据开关，没有传入 `COOKIE_SECRET`。因此按 README 复制并修改 `.env`，这些配置不会按预期进入容器。生产会话还固定设置 Secure（`auth.ts:48`），需要明确 NAS 局域网 HTTP 与 HTTPS 反向代理的支持方式，不能只验证 localhost。

**工作：** 生产缺少有效密钥时拒绝启动，修正 Compose 配置传递，更新部署说明，并补登录、未登录、过期会话及部署模式测试。

**验收：** 修改配置能改变实际容器配置；默认公开密钥无法获得授权；目标 NAS 访问方式能够完成登录并访问后续 API。

### P0：直传返回空响应；P1：播放状态和错误恢复

**已复现的播放阻断：** `src/server/routes.ts:24` 的 `sendFileRange()` 返回 void，`:159` 的异步路由随即返回 undefined。临时服务通过真实 HTTP 请求一个 10 字节样本，整文件请求返回 200、Content-Length 为 0；Range 请求返回 206，但响应体同样为空。对照正确返回 `reply.send(stream)` 的路由能返回完整内容。该缺陷影响走直传路径的音频，应与生产鉴权一起优先修复。

**其他已确认问题：** `routes.ts:36` 的 Range 解析将 `bytes=-3` 当作从 0 开始的区间；10 字节样本返回 `bytes 0-3/10`。合法的超出文件尾部的上界也被直接判为 416。FFmpeg 启动/退出错误没有完整处理（`:180`），前端播放失败主要写入控制台（`App.tsx:635`），缺少加载失败、卡顿及重试反馈。

**工作：** 修复异步路由的响应返回，补齐直传与 Range 响应验证，处理 FFmpeg 失败和客户端断开，建立播放器加载、播放、暂停、失败状态。保持 AAC M4A 直传、ALAC M4A 转码规则。

**验收：** MP3、AAC M4A、ALAC M4A、FLAC 样本都能首播、拖动、暂停恢复和自动切歌；响应体实际含音频数据；失败可见且可重试；切歌后没有遗留转码进程。桌面与真实手机分别验证，不能只观察播放按钮。

**扫描与数据可靠性（P2）：** 当前每次扫描都逐文件解析，在线补全串行放在扫描流程内（`scanner.ts:161`）。优先利用已有 size/mtime 跳过未变更文件，再将在线补全独立为可重试任务。增加服务重启后残留 running 扫描的恢复、取消/进度，以及 DATA_DIR 备份恢复说明。现有空目录和解析失败保留索引的保护应继续保留；部分挂载丢失时的清理策略需用临时目录验证。路径变化后的收藏/歌单保留策略需要明确，不能默认绝对路径 ID 能跨挂载迁移。

**在线补全（P2）：** 失败/无结果缓存尚无过期或强制刷新机制（`metadata.ts:287`、`:332`）；完整标签但缺失封面的补全路径也需补齐。以断网后恢复、服务暂时失败、仅缺封面等场景验收，保持所有补全结果写入 DATA_DIR。

**手机与 PWA（P2，手机优先时提前）：** 现有移动 UA 布局已实现；iPad 按桌面/平板处理。尚未发现 manifest、Service Worker 或 Media Session 实现，README 的 Web/PWA 定位尚未落实。先做真实 iPhone/Android 的首播、后台、锁屏、耳机控制和网络恢复验收，再补安装图标、独立窗口、升级/离线提示与媒体控制。离线缓存整首音频属于独立需求，不默认纳入首轮。

**工程维护（随功能推进）：** `App.tsx` 约 2282 行、`styles.css` 约 4077 行。按播放器状态、歌词、数据请求和页面逐步拆分；先为行为补测试，再做对应拆分。补 CI 执行类型检查、测试和构建，并记录支持的 Node 版本。后续部署验证应覆盖 Docker 构建、数据持久化、重启恢复和备份还原。

## 6. 还需确定的产品取舍

- 主要入口是桌面还是手机：决定手机验收、锁屏控制和 PWA 的排序。
- 目标曲库规模：先用 61/201 的边界数据消除截断，再按真实规模决定是否需要虚拟列表或额外索引。
- NAS 访问方式：局域网 HTTP、VPN 或 HTTPS 反向代理，会影响部署说明和会话配置。
- 是否要求关闭浏览器后续播、无缝播放或离线听歌：这些都需要明确范围，不能从已有播放器或 PWA 文案推定已支持。
