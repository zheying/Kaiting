# 专辑页窄桌面布局修复

> 隐私说明：环境地址和路径已替换为示例；原始验收附件在仓库外私有保存，不随仓库发布。

日期：2026-09-22。针对用户在 549 × 829 桌面窗口中的批注，修复专辑标题过窄和曲名列消失。仅修改 `src/client/styles.css`。

## 原因与调整

原专辑行的序号、格式、时长及操作列加上间距与内距需要至少 328px。在实际页面中，曲名列宽度已经变成 0；横排封面还将长标题挤到约 128px。

- 1040px 及以下桌面窗口收起专辑名、格式列，给曲名留出可用空间。
- 760px 及以下桌面窗口，详情改为封面与介绍上下排列；标题 24px 并均衡换行，内容水平内距减为 18px。
- 同一窄桌面断点收起曲序，保留播放、曲名与艺人、时长、更多操作。
- 窄窗口的歌单子菜单改为在菜单内部展开，解决原先向左弹出屏幕的问题。
- 所有新规则均限定 `.app-shell:not(.mobile-shell)`。桌面 480px 最小宽度、移动 UA 判断和全屏播放器样式保持原实现。内距变量只作用于内容区。

## 验证

- `npm run typecheck`、`npm run build`、`git diff --check` 通过；Docker ARM64 镜像构建通过。此次只改 CSS，未重复运行后端测试。
- 临时环境使用正式 SQLite 的一致性副本、只读 NAS 音乐卷和只读封面目录。
- 549px：曲名列从 0px 恢复为约 182px；标题可用宽度约 332px。正文无额外横向溢出。
- 480px：曲名列仍有 134px；480px 最小页面宽度仍然生效。
- 640、760、761、1040、1041、1280px：曲名列均大于 0，时长及菜单按钮可见，宽屏恢复完整列。尺寸记录见 `viewport-checks.json`。
- 首页普通列表在 549px 下同样保留约 182px 曲名空间。
- 歌单子菜单在 549px 下位于 x=222–500，在 480px 下位于 x=168–446，均在可见范围内。
- 临时环境通过歌曲行播放真实 FLAC，播放时间推进至 6.57 秒，音频无错误，随后暂停。
- 本轮没有真手机或移动 UA 实机验收；移动规则通过选择器隔离检查。
