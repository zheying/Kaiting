# 手机尺寸布局与播放体验修复

> 隐私说明：环境地址和路径已替换为示例；原始验收附件在仓库外私有保存，不随仓库发布。

日期：2026-09-23。用户在 393 × 852 窗口批注专辑页被桌面侧栏和最小宽度撑出横向滚动。

## 修复

- `useMobileLayout()` 保留手机 UA 优先判断，并为非 iPad 浏览器增加小于 480 CSS px 的移动布局兜底。跨过断点即时切换；iPad/iPadOS 继续使用桌面或平板布局。
- 手机页面收起固定桌面侧栏，使用顶部导航入口。关闭导航时侧栏不可聚焦；打开时锁定背景滚动与交互，Tab 焦点保持在导航内，Escape 关闭并回到入口。退出登录或切回桌面都会释放锁定。
- 搜索与扫描按钮合并为一行，移除无实际操作的账户按钮；专辑封面缩小，长标题均衡换行，曲名优先获得宽度，播放及菜单按钮具有 44px 触控区域。
- 修复底部播放器继承桌面定位导致右移的问题，使用实际可用宽度并留出安全区。
- 手机全屏播放页按可用视口高度约束封面和间距，进度条触控高度 44px，播放与队列切换按钮保持可见；短屏保留内部滚动兜底。
- 手机歌词和待播清单独立分配滚动区域，避免与全屏控件重叠；不再重复显示桌面歌词面板。

## 验证

- 类型检查、生产构建、`git diff --check` 通过。
- 23 个测试文件、372 项测试通过，其中新增 21 项布局选择测试，覆盖手机 UA、iPad/iPadOS、393px、小数宽度、480px 边界、触屏桌面和 SSR。
- 使用正式数据库的一致性副本运行临时验收服务，音乐和封面只读挂载。
- 专辑页在 320 / 393 / 430 / 479px 下使用移动布局，`scrollWidth` 与可用宽度一致，没有横向溢出；曲名列分别为 119 / 192 / 229 / 278px。
- 480 / 549 / 1280px 正常切回桌面。480px 保留原桌面最小宽度策略；549px、1280px 不产生额外横向溢出。
- 导航打开后正文和播放器带 `inert`，Tab/Shift+Tab 在关闭入口与退出按钮之间循环，Escape 后焦点回到打开入口；导航打开时切到 549px，会关闭导航并恢复滚动。
- 真实 NAS FLAC 播放时间推进到 15.25 秒，音频无错误，随后暂停。打开全屏、切换待播清单和关闭全屏均可完成。
- 320 × 568 的全屏播放布局高和滚动高度均为 568px；底部切换区位于 500–556px。393 × 852 和 430 × 932 的全屏布局也没有额外纵向溢出。
- 320 × 568 的队列列表可独立滚动，播放控件底部为 500px，底部切换区仍可见；393px 下完整队列为 10 首待播歌曲。
- 手机搜索 REMAKE 返回 297 首歌曲、10 张专辑，当前页 25 首；无横向溢出，无浏览器错误日志。
