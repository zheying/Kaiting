# Music Library 当前 UI 审计

> 隐私说明：环境地址和路径已替换为示例；原始验收附件在仓库外私有保存，不随仓库发布。

审计日期：2026-09-22。目标是判断目前界面是否适合每天使用的个人 NAS 音乐播放器。实测对象为已部署服务 <http://192.0.2.10:3002>，使用已登录的桌面浏览器，覆盖首页、专辑、搜索、空歌单、播放页和待播清单。

**整体判断：视觉风格已经统一，但播放操作的可靠性和找歌效率仍需优先改善。** 浅色界面、红色选中态、封面卡片、底部播放器以及播放页的封面取色背景可以保留。当前最影响日常使用的两项问题是：较矮窗口中播放控件被裁切，以及键盘移动焦点会重新加载转码音频。

截图均为本轮真实服务的原始浏览器截图，已逐张保存并打开检查；没有裁剪、重绘或使用旧截图。01–04 文件为 1265×712，05、06、08 为 1280×720，07 为临时设置的 1280×900 对照图。尺寸结论以第 06 步实测 DOM 几何为准，不把图片文件尺寸当作所有页面的视口尺寸。

**逐步审计**

1. **首页——需要改善信息优先级。** 导航位置和选中态清楚，整体风格一致。但大标题、全库数量与三张运行状态卡占据首屏主要空间，“最近加入”靠近底部播放器。错误卡只显示截断英文，缺少文件定位和下一步处理入口。对应问题 5。

   原始截图已转存私有验收资料。

2. **专辑列表——浏览可用，专辑识别困难。** 封面比例和间距稳定。同名同封面的《Xenoblade Definitive Edition》连续出现六张卡，只在艺人上不同；长标题和艺人同时截断，难以判断是不同版本还是同一专辑的分片。对应问题 3、7。

   原始截图已转存私有验收资料。

3. **专辑详情——主动作清楚，信息密度失衡。** 从光田康典的上述卡片进入后只有两首歌曲、约十分钟。长日文标题分成四行，占据大量首屏；顶部缺少足够的分组身份信息，歌曲行又重复同一长专辑名。对应问题 3、7。

   原始截图已转存私有验收资料。

4. **搜索——结果能加载，但数量与层级误导。** 搜索 `REMAKE` 后有播放全部结果入口。顶部却继续展示全库 1044 首、87 张专辑、59 位艺人；实际匹配数为 297 首、74 张专辑、0 位艺人，位于各分类底部。专辑结果排在 25 首歌曲之后。对应问题 4、6。

   原始截图已转存私有验收资料。

5. **空歌单——空态较完整，焦点恢复有缺陷。** 返回、空态说明和“前往曲库添加歌曲”入口明确；播放与排序在空列表禁用。打开删除确认后点击取消，焦点落到 BODY，没有回到删除按钮。这里只检查并取消确认，没有执行删除。对应问题 6。

   原始截图已转存私有验收资料。

6. **播放页，1280×720——存在核心操作障碍。** 大封面与背景氛围统一，但播放、切歌控件大部分落在可见区域之外，音量完全在下方。页面内容高 854px，容器高 720px 且隐藏溢出。对应问题 1。

   原始截图已转存私有验收资料。

7. **播放页，1280×900 对照——布局恢复，键盘操作仍异常。** 同宽加高后主要控件完整显示，证明第 06 步问题与可用高度有关。另在此视图实测：FLAC 播放时，仅从“更多”按钮按 Tab 到进度条就更换转码流并重新缓冲。对应问题 1、2。对照后已恢复默认视口。

| 编号 | 优先级 | 问题与影响 | 建议与验收标准 |

| 1 | P1 | 第 06、07 步：1280×720 下播放按钮顶部在 y=713、高 48px，上一首/下一首在 y=717，音量在 y=784。核心鼠标操作被裁切。 | 先为控制区预留高度，再按剩余空间缩放封面；必要时允许内容区滚动。至少验收 1280×720、1366×768 和 1280×900，播放、切歌、进度与音量始终可达。保留现有桌面最小宽度和移动 UA 分支。 |

**复现证据与实现定位**

- 问题 1：播放页几何记录（原始附件已转存私有验收资料）。当前样式 `src/client/styles.css:1815` 按宽度设置封面大小，`:1676` 起的播放层隐藏溢出；应整体核算可用高度，不简单解除全局滚动锁。
- 问题 2：Tab 前后媒体状态（原始附件已转存私有验收资料）。原媒体片段起点 97.126899 秒、片段内时间 6.800924 秒，合计约 103.927823 秒；Tab 后换为起点 104 秒的新片段，片段内时间归零。这里是**重新载入并缓冲**，不是歌曲跳回开头。`src/client/App.tsx:1597` 起的进度键盘事件以及 `:1133` 的底部进度事件需要限制触发条件。
- 问题 3：`src/server/db.ts:391` 按专辑名与 `COALESCE(album_artist, artist)` 分组；`:589` 的详情查询使用相同键，没有分页截断。缺少或不一致的专辑艺人标签可产生拆分，但本轮未逐文件核对标签，因此不把某一种标签缺陷写成已证实根因。修复不得改写 NAS 曲库文件。
- 问题 4：搜索完整 DOM（原始附件已转存私有验收资料） 记录了三个分类的实际数量和分页状态。
- 问题 6：取消后的焦点记录（原始附件已转存私有验收资料） 为 BODY。`src/client/PlaylistView.tsx:76` 负责打开时聚焦，取消后缺少对应恢复。没有将这一结论扩展为所有弹层都已实测。
- [逐步采集记录](capture-notes.md) 与 原始截图索引及 SHA-256（原始附件已转存私有验收资料） 保留本轮证据。

**验证边界**

本轮实测了桌面浏览器的页面呈现、搜索、导航、播放/暂停、Tab 操作、确认取消及队列收起。没有测试真实手机 UA、触摸、锁屏/后台播放、读屏器、200% 缩放或正式色彩对比度，因此不对移动端质量或完整无障碍合规作结论。焦点、按钮名称与控件裁切属于本轮有证据支持的问题。

本轮只新增审计文档和截图，没有修改应用代码、NAS 音乐文件、歌单或收藏；结束时恢复默认视口、关闭队列、回到首页，并暂停音乐。文档检查使用 `git diff --check`，未因仅文档审计重新运行应用构建与测试。

**建议下一轮：先完成问题 1、2 的播放页高度与进度键盘修复，并按上述场景复测；随后处理专辑分组和搜索信息层级。**
