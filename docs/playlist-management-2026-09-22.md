# 歌单管理交付记录

目标：完成日常听歌所需的歌单整理流程，同时保留正在播放的队列和只读曲库约束。

## 功能与约定

- 歌单详情支持重命名、删除确认、移除歌曲、调整并保存歌曲顺序；空歌单提供前往曲库添加歌曲的入口。
- 调整顺序使用独立草稿和上移/下移按钮，支持保存或取消。编辑歌单不会改动当前播放队列；下次播放歌单使用保存后的顺序。
- 名称去除首尾空白后为 1–200 个字符。删除只清理歌单及关联，不删除歌曲、收藏或音乐文件。
- 创建、添加和编辑具有提交中状态和失败反馈。创建歌单成功、随后添加歌曲失败时，重试复用已创建的歌单，避免重复创建空歌单。
- 同一页面对同一歌单的修改互斥；离开页面后，旧请求结果不会覆盖新页面。

## 数据与接口

新增 `PlaylistDetail = { playlist, tracks, revision }`。版本由歌单 ID、名称、描述和有序歌曲 ID 生成，跨重启稳定，不受其他歌单或歌曲收藏变化影响。

| 接口 | 用途 |
| --- | --- |
| `PATCH /api/playlists/:id` | 请求 `{ name }`，返回更新后的歌单概要 |
| `DELETE /api/playlists/:id` | 删除目标歌单及关联，返回 `{ ok: true }` |
| `PUT /api/playlists/:id/tracks/order` | 请求完整的 `{ trackIds, revision }`，原子保存顺序 |
| `GET /api/playlists/:id` | 返回带版本的完整详情 |
| `POST /api/playlists/:id/tracks` | 幂等添加并返回详情 |
| `DELETE /api/playlists/:id/tracks/:trackId` | 幂等移除，返回 `{ ok: true, ...detail }`，保留旧接口字段 |

修改成员和顺序使用 SQLite `IMMEDIATE` 事务。排序只接受完整无重复的成员排列；旧版本或成员不匹配返回中文 `409`，不写入部分结果。非法类型返回 `400`，不存在的歌单返回 `404`。嵌套歌曲 ID 在参数自动转换前严格校验。移除后连续编号，重新添加的歌曲排在末尾。

浏览器收到排序冲突时保留草稿并禁止继续保存，用户可放弃草稿、重新加载后再调整。

## 验证记录

自动化测试覆盖歌单生命周期、数据库重开持久化、外部连接修改、并发排序、非法排列原子回滚、重复增删、删除隔离，以及浏览器客户端与实际 Fastify/SQLite 的接口合同。前端状态测试覆盖草稿与播放快照分离、修改互斥、创建后添加失败的重试及重复点击合并。

`npm test` 共 16 个文件、248 项通过（本轮新增 45 项）；类型检查、生产构建与差异检查通过。

桌面浏览器验收使用临时生成的 4 首静音 MP3 和独立 `DATA_DIR`，验证结果如下：

- 创建空歌单，使用歌曲菜单添加 3 首；歌单数量与总时长正确。
- 歌曲菜单“创建并添加”及全屏播放页添加到已有歌单成功，列表计数同步。
- 名称含中文、斜杠与百分号可保存，保存后立即进入排序不会误报冲突。
- 上移/下移后取消恢复原顺序；保存后详情顺序更新。原播放进度从 0:05 继续到 0:13，待播歌曲保持原顺序；再次播放歌单采用新首曲。
- 服务重启、页面刷新后，名称与保存的顺序保留。
- 停止临时服务后，重命名保留输入并显示中文连接错误；恢复服务后直接保存成功。
- 移除歌曲失败时保留歌曲和重试入口；服务恢复后“重试移除”成功。
- 两个页面同时编辑：另一页面改名后，旧排序提交显示冲突，保留草稿并禁用保存；重新加载恢复服务端名称与顺序。
- 歌单内收藏后菜单同步为“取消收藏”；移除最后一首显示空态，播放与排序禁用。
- 删除确认支持取消；确认后返回歌单列表，当前歌曲与待播队列保留。旧详情页刷新显示不存在与返回入口。
- 删除后数据库仍有全部 4 首歌曲、1 个收藏，4 个音乐样本文件仍存在。原有数据库的 1,054 首歌曲、收藏、2 个歌单及成员记录与验收前一致。

审查还修复了创建后添加失败的重复空歌单风险，以及重命名刷新时旧版本/错误状态的竞态。验收结束后停止临时服务并清理临时曲库、数据库和浏览器标签页。

## 后续范围

本轮不改变播放队列编辑功能，也不包含正式 NAS 部署或真实手机后台/锁屏验收。长期使用的下一项建议是扫描恢复与增量扫描，以及 `DATA_DIR` 的备份/恢复流程。
