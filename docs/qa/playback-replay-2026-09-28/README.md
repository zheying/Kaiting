# 播放结束后重播修复验收

> 隐私说明：环境地址和路径已替换为示例；原始验收附件在仓库外私有保存，不随仓库发布。

日期：2026-09-28。

## 原因与修复

FLAC / ALAC 跳转后使用从指定时间开始的转码流。原实现播放结束后直接调用 `audio.play()`，可能只重播最后一段流，同时保留旧的时间偏移。刷新恢复已完成的播放位置时，还会请求从曲尾开始的空转码流。

- 自然结束后明确记录完成状态，释放旧音频流；再次播放重新加载原曲 0 秒。
- 已完成的持久化播放位置恢复为暂停的完成状态，不请求曲尾空流。
- 进度拖到末尾时，播放中按队列规则切歌，暂停时保持完成状态；后续重播从零开始。
- 普通暂停保留原进度，包括靠近末尾但尚未完成的位置。
- 首页已完成曲目的按钮可访问名称为“重新播放”；首页、胶囊播放器、全屏播放器共用同一套逻辑。
- 保持既有 AAC M4A 直传、ALAC M4A 转码规则，未改变页面样式。

实现：`src/client/room/player.ts`、`src/client/room/playback-position.ts`、`src/client/room/Room.tsx`。

## 实际浏览器回归

使用独立的临时 DATA_DIR 和新生成的静音测试音频，不改动实际曲库。浏览器通过正常界面登录、扫描、播放和拖动进度，没有注入播放器内部状态或伪造 ended 事件。

| 场景 | 观察结果 |
| --- | --- |
| 24 秒 FLAC 跳转到 10 秒后自然结束，再点首页重新播放 | 0:24 → 0:00，重新请求完整流，不再重播尾段 |
| 暂停后拖到末尾 | 保持 0:24 完成状态，按钮为“重新播放” |
| 完成后刷新，再点重新播放 | 仍能从 0:00 开始，恢复时没有曲尾流请求 |
| 在 2 秒处暂停、继续 | 保留 0:02 位置 |
| AAC M4A 自然结束后重播 | 0:24 → 0:00，仍使用直传 |
| AAC M4A 播放中拖到末尾后重播 | 正常停止，随后从 0:00 开始 |
| 两首歌的队列自然结束第一首 | 自动播放第二首 |
| 列表循环时最后一首拖到末尾 | 回到第一首 0:00 |
| 单曲循环 | 同一首从 0:00 重新加载 |
| 全屏播放器完成后点播放 | 0:24 → 0:00，按钮变为暂停 |

转码请求证据：`stream-requests.json`（原始附件已转存私有验收资料）。其中包含 `start=10`、普通完整流重播、队列切换；没有 `start=24` 曲尾请求。
