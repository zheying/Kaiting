# 原型多余滚动检查

日期：2026-09-28。范围：状态总览的 59 个入口，在桌面 1108×879、手机 393×852 下分别采集截图与布局尺寸；另抽查曲库载入、曲库错误、目录不可访问、设置、搜索、歌曲格式筛选 6 个正式入口。对下述问题与正常对照进行了截图复核。

结论：仍有多组短内容页面因空态高度与页头、底部留白叠加，出现不必要的滚动。最需要调整的是目录错误、扫描失败、账号列表状态以及歌曲格式筛选空态。本轮仅检查并保存证据，没有修改应用代码或提交 Git。

表中为主内容区域实测的可滚动距离，单位为 CSS px。它是定位依据，不表示每一像素都必须消除。没有将正常长列表、真实长表单、详情骨架或沉浸播放器背后的专辑页滚动判为缺陷。

## 1. 目录不可访问与扫描异常：需调整

| 状态 | 桌面 | 手机 |
| --- | ---: | ---: |
| 目录不可访问，正式入口 | 141 | 285 |
| 目录不可访问，预览入口 | 177 | 341 |
| 无法启动扫描，预览入口 | 177 | 179 |
| 扫描中断，预览入口 | 177 | 179 |

错误提示本身很短，但面板仍占接近一整屏。目录错误在手机上又将检查信息排在面板下方，大片留白把诊断信息推到首屏以外。桌面扫描失败也出现明显空白滚动。

证据：[手机正式目录错误](mobile-actual-directory.jpg)、[桌面扫描失败](desktop-scan-failed.jpg)。

原因：`shell.css:268` 和 `shell.css:373` 对 `.state-panel.is-error` 应用整屏高度计算。其选择器优先级高于 `catalog.css` 的局部空态规则，放入有页头的页面或 `.incident-state` 内仍沿用整屏高度。应按实际剩余区域布局；移动端的诊断信息与恢复操作应组成一块紧凑内容。

## 2. 账号列表载入、失败和搜索无结果：需调整

| 预览状态 | 桌面 | 手机 |
| --- | ---: | ---: |
| 账号列表载入中 | 47 | 约178 |
| 账号列表载入失败 | 47 | 178 |
| 账号搜索无结果 | 89 | 179 |

页头、账号标签、统计、筛选占据上半屏，空态又保留固定高度。手机首屏的“重新载入”或“查看全部账号”靠近底部播放器，部分被遮住；桌面无结果页面的底部说明也被挤下去。

证据：[手机账号载入失败](mobile-accounts-error.jpg)、[桌面账号搜索无结果](desktop-accounts-empty.jpg)。

原因：`accounts.css:105` 将 `.account-empty` 固定为至少 350px，手机规则仍有 330px，而页面外层没有根据剩余空间分配高度。建议缩减空态上下留白，无结果时同时移除空表头；内容确实超长时继续允许正常滚动。

## 3. 歌曲格式筛选无结果：需调整

正式 `#/songs` 点击 FLAC 后，桌面可滚动 71px，手机 178px。筛选栏与空态之间留白很大，返回全部歌曲的按钮偏低。

证据：[桌面 FLAC 空态](desktop-actual-songs-empty.jpg)、[手机 FLAC 空态](mobile-actual-songs-empty.jpg)。

原因：`catalog.css:132` 对直接子空态使用 `100dvh - 300px`，没有扣除当前页头、筛选栏和底部播放器的实际占位。应沿用已调整的歌单空态布局，以剩余高度居中内容。

## 5. 其他轻微溢出的预览页：需统一高度规则

| 预览状态 | 桌面 | 手机 |
| --- | ---: | ---: |
| 首次设置、曲库为空、没有专辑、没有艺人 | 各42 | 各0 |
| 扫描未发现音乐 | 约42 | 0 |
| 扫描进行中 | 22 | 0 |

这组以桌面轻微空白滚动为主。预览页额外的“状态总览 / 交互预览”导航占用了高度，但状态面板仍沿用固定视口减值。正式 `#/setup` 本次显示的是“已选择目录、等待扫描”的曲库为空分支，桌面也有 6px 溢出；没有把它误记成首次未选目录分支。

证据：[桌面首次设置](desktop-setup-empty.jpg)、[桌面扫描进行中](desktop-scan-running.jpg)、[手机页面不存在](mobile-not-found.jpg)。

## 6. 对照与排除项：本次未发现同类问题

- 空歌单集合、单张空歌单、空收藏：两种尺寸下主区域滚动距离均为 0。
- 扫描全部成功、登录错误/断线/过期等状态：两种尺寸下没有同类空白滚动。
- 正式 `#/loading` 与 `#/error`：两种尺寸下主区域滚动距离均为 0。
- 专辑曲目、已有歌单、搜索结果、资料与安全页面：内容本身超过屏幕，不能仅凭存在滚动条认定异常。
- 详情加载骨架延续曲目列表结构；“下一页载入失败”包含已载入歌曲，其滚动未记为缺陷。
- 全屏待播清单的底层专辑页存在滚动范围，不等于当前全屏面板发生滚动；空队列手机截图未见外层多余滚动条。
- 采集的两种尺寸中未检测到根文档横向溢出。

优先修复 1–4，再统一 5 的预览高度。建议复用已处理歌单空态的弹性剩余空间布局，同时保留长内容所需的自然滚动；不要用 `overflow: hidden` 遮蔽问题。

原始测量：[measurements.json](measurements.json)。全量截图与尺寸索引：[measurements.md](measurements.md)。当前证据来自 IAB 的两种视口尺寸，不代表所有屏幕高度和 Chrome/Safari 均已验证；本轮没有进行全面无障碍审查，也未运行构建测试（无应用代码改动）。
